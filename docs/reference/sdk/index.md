# Plugin SDK

The C++ API for native plugins: peripheral models and bus devices built against popcorn's headers
and loaded at run time. The [native plugins guide](../../guide/native_plugins.md) shows how to
write one.

[Open the API reference](api/index.html){ .md-button }

The reference is generated by doxygen from the public headers a plugin includes:

- `popcorn/plugin/`, the plugin entry point, the ABI tag and the bindings helpers.
- `popcorn/export.hpp`, the symbol visibility macros.
- `popcorn/core/`, `types.hpp`, `errors.hpp`, `fwd.hpp`, `services.hpp`, `machine.hpp`,
  `clock.hpp`, `scheduler.hpp` and `description.hpp`.
- `popcorn/periph/`, `model.hpp`, `register_file.hpp`, `lines.hpp`, `spi.hpp`,
  `uart.hpp`, `reset_listener.hpp` and `snapshot_listener.hpp`.
- `popcorn/periph/stm32/gpio.hpp`, the GPIO port interface with its pin watchers.

The `uart_endpoint` interface in `uart.hpp` is the far end of a UART in C++. It hears each frame the
firmware transmits, `ending()` with the whole frame, and `heard_format()` sets the format it reads
them in. Frames queued through `uart_port` take a line format of their own. The
[UART devices guide](../../guide/uart_devices.md) shows the Python device on the same port.

The reference covers the headers listed above.

Doxygen renders the pages with the doxygen-awesome-css theme, so their look differs a little from the rest of this site. Every declaration
that doxygen extracts from these headers carries a doc comment, and the docs build fails when one
is missing.
